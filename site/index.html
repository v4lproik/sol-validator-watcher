A unified operator product surface with room for economics

Coverage is not buried. Container usage is not hidden in CI. Dashboard previews already have a place in the layout, and the roadmap now clearly points toward Jito, Harmonic, and per-block revenue views.

What the watcher gives you out of the box

Today it covers the operational core. The direction is to widen that same surface into an operator cockpit for both technical and economic performance.

Watched-validator metrics Vote lag, root lag, commission, blocks produced, blocks missed, and future leader slots.
Scope-aware fleet views Track `scope:watched`, `scope:network`, `scope:all-network`, and your own custom slices.
Graceful degradation Core metrics keep flowing even when optional provider methods like `getBlockProduction` are unavailable.
Economics roadmap Next metrics should include Jito revenue, Harmonic revenue, base revenue per block, and normalized block economics.

Coverage lives inside the product site

Pull the image from GHCR

The container workflow publishes branch, tag, SHA, and `latest` tags to GitHub Container Registry on pushes to the default branch and release tags.

Pull

docker pull ghcr.io/v4lproik/sol-validator-watcher:latest

Run

docker run --rm \
  -p 8000:8000 \
  -v "$(pwd)/etc:/app/etc:ro" \
  ghcr.io/v4lproik/sol-validator-watcher:latest \
  --config /app/etc/config.devnet.yaml
