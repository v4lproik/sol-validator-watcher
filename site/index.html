Operator workflow

From signal to answer in one surface.

Start with process readiness and validator state, diagnose against network context, then verify recovery through clean polling rounds.

  1. 1

    Detect

    Find what needs attention.

    Health, readiness, and watched-validator state make the first failure visible without searching across tools.

  2. 2

    Diagnose

    Compare it with the network.

    Vote lag, root lag, skip rate, stake, source provenance, and provider outcomes keep the signal in context.

  3. 3

    Verify

    Observe a clean recovery.

    Five consecutive clean polling rounds restore readiness while failed modes and stale snapshots stay explicit.

RPC · WebSocket · provider APIs → Rust exporter → Prometheus → Grafana · Alertmanager

Built for operator truth

Useful when the data is imperfect.

No silent zeros, hidden connector changes, or one-endpoint assumptions.

Per-command source routing

Declare ordered connector routes once. The first successful compatible connector wins, and the selected source is exported.

Missing stays missing

Optional rewards and unavailable samples remain no data instead of becoming healthy-looking zero values.

Economics beside performance

Inflation rewards, produced blocks, recent block fees, Jito rewards, commission, and funding runway share one operating view.
